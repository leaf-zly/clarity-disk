# 澄盘功能说明书

> 版本：0.5 · 日期：2026-08-14 · 文档状态：计划七分区安全基础基线

## 1. 文档说明

这是一份面向产品、设计、开发、测试和发布团队的功能说明书。它描述“澄盘”要解决的问题、每一个功能的使用方式、展示信息、权限边界、失败处理和验收条件。

状态标记：

- **已完成**：仓库中已有可运行实现，并通过对应质量检查。
- **开发中**：技术路线已确定，正在拆分为代码任务。
- **规划中**：已列入产品范围，但必须完成前置安全评审后才能实现。
- **受限功能**：涉及删除、管理员权限、重启或分区写入，默认不可直接执行。

## 2. 产品定位

澄盘是一款 Windows 本地磁盘管理工具，核心价值是“看得清、删得稳、改得明白”。它先通过只读扫描建立可信信息，再让用户查看影响、确认操作，最后由受控执行层完成低风险维护。产品不以“一键清理所有文件”为目标，不隐藏风险，也不把未知文件误判为垃圾。

## 4. 详细功能描述

### F01 首页仪表盘（已完成）

**目的**：让用户打开应用后，在一个页面内理解当前磁盘状态。

**页面内容**：

- 顶部问候语、当前状态摘要和“开始智能扫描”按钮；
- 系统盘总容量、已使用容量、可用容量和使用百分比；
- 应用、系统、文件、开发缓存等空间分类；
- 智能清理建议卡片，显示预计可释放空间和风险等级；
- 磁盘健康、上次清理、自动维护等状态卡片；
- 本月累计释放空间和最近维护活动。

**交互规则**：

1. 页面加载时显示骨架或加载状态。
2. 数据读取失败时显示可理解的错误和重试按钮。
3. “开始智能扫描”只启动扫描，不直接删除文件。
4. 浏览器模式使用 fixture，桌面模式通过 Tauri command 获取数据。

**安全边界**：首页不接受路径、不执行 shell、不直接访问文件系统。当前清理建议和健康信息中仍有演示数据，界面必须保持“预览”语义。

**验收**：桌面布局、响应式布局、键盘操作、错误状态和 4 个现有前端测试均通过。

### F02 磁盘与卷发现（已完成只读基础版）

**目的**：发现 Windows 中的物理磁盘、逻辑卷和挂载点，建立后续扫描和分区操作的稳定身份。

**当前已读取**：基础卷发现读取盘符/挂载点、卷标、文件系统、总容量、可用容量、设备类型、系统卷、可移动、只读和基础健康状态；计划六补充物理磁盘唯一标识、分区 GUID、起始偏移、分区容量、GPT/MBR、BitLocker、动态磁盘、存储空间、卷影副本、磁盘/卷健康与介质可靠性计数。F11 在相同物理磁盘身份上补充温度、磨损、通电时间、错误计数、固件、介质、扇区和加密汇总。

**用户看到的内容**：

- 磁盘列表和卷列表；
- 盘符不是唯一身份的提示；
- 系统卷、数据卷、可移动设备的标签；
- 不可访问、离线、加密或健康异常的原因。

**失败处理**：设备断开、权限不足、查询超时或字段不完整时，保留已获取的只读结果，并标记“数据不完整”，不生成任何写操作计划。

**安全边界**：只读 API；不格式化、不挂载、不修改卷标、不改变分区。

### F03 空间扫描（已完成）

**目的**：定位空间主要消耗者，为清理建议和容量分析提供证据。

**扫描范围**：用户选择的卷、目录或预设范围。预设范围包含系统临时目录、用户缓存目录、应用数据目录和开发工具缓存目录。

**扫描结果**：目录树、文件类型统计、最大文件列表、最近访问时间（若系统允许）、可跳过原因和扫描不完整标记。

**默认排除**：用户文档、桌面、下载目录、项目源码、符号链接、联接点、重解析点、虚拟文件、系统关键目录和锁定文件。

**性能要求**：低优先级运行，支持取消；不一次性把全部文件名载入内存；扫描结果可增量显示；单个异常文件不能中断整个任务。

**当前实现**：支持用户输入扫描范围、逐行配置排除目录、最大深度和最大条目数；排除目录会在 Rust 层规范化并限制在扫描根目录内。后台线程只读遍历目录，跳过符号链接、不可读项和并发消失项，单个子目录异常不会中断任务。结果每 128 个条目发布一次，持续返回最大文件、聚合目录、文件类型、读取字节数和跳过数量。浏览器模式提供增量 Fixture，桌面模式通过 Tauri 命令读取本机目录。

**验收结果**：扫描文件内容保持不变；深度、条目和排除范围均有 Rust 测试；路径越界会拒绝启动；Vue 黑盒测试覆盖配置提交、增量结果、最大项目和文件类型展示。

### F04 扫描任务控制（已完成）

**目的**：让用户可以控制长时间扫描，不被不可预测的进度卡住。

**功能项**：开始、暂停、继续、取消、后台运行、限制扫描深度、限制 CPU/磁盘优先级、显示当前目录和预计剩余时间。

**状态机**：`待开始 → 扫描中 → 暂停 → 扫描中 → 已完成/已取消/失败`。终态不可重新变更；重新扫描必须生成新的 `scan_id`。

**异常**：取消后在安全边界停止，不强制终止系统线程；应用关闭时保存“未完成”状态，不把不完整结果标为完整。

**当前实现**：扫描任务拥有独立 `scan_id`，支持后台运行、每 400 毫秒轮询、协作暂停、继续和取消；达到深度或条目上限时安全停止。进度百分比和剩余时间明确标为基于条目上限的估算。终态会停止轮询并持久化到 `%LOCALAPPDATA%\ClarityDisk\state\space-scan-history.json`，最多保存 20 条；损坏的历史文件会被安全忽略。

**状态与交互**：扫描中显示暂停和取消，暂停时显示继续和取消；组件卸载会释放轮询计时器，但不会隐式终止后端任务。完成、取消或失败后刷新本机历史，错误使用用户可读文案展示。

### F05 清理规则中心（计划二只读版已完成）

**目的**：把“什么可以清理”从 UI 中抽离为可测试、可版本化的 Rust 规则。

**当前规则**：Chrome、Edge 和 Brave 默认用户配置的浏览器缓存目录、Windows 缩略图数据库（`thumbnail-cache.v1`）、用户临时目录（`user-temp.v1`）、系统回收站（`recycle-bin.v1`）以及常见包管理器/开发工具缓存（`build-cache.v1`）。扫描器只读取允许根目录内的元数据和文件大小，跳过符号链接、不可访问项和并发消失项；临时目录、回收站和构建缓存默认需要复核，不自动选中。

**Windows 更新规则**：`windows-update-download-cache.v1` 仅扫描 `%SystemRoot%\SoftwareDistribution\Download`，为需单独确认、默认不选中、未来执行需管理员权限。本阶段不停止服务、不删除、不请求提权。休眠文件仍在后续规划中。

**当前证据模型**：每个候选包含规则版本、发现证据、项目数、容量、恢复策略、管理员权限和隔离区资格；每个启用规则即使无候选，也返回“可用、为空或不可用”状态与安全原因。

**每条规则必须说明**：规则 ID、版本、扫描范围、发现证据、文件数量、预计释放容量、风险等级、是否可恢复、是否需要管理员权限、默认是否选中。

**风险分级**：

- `Safe`：可再生缓存，删除后应用会重新生成；默认可选中。
- `Review`：可能影响历史记录、登录状态或应用体验；默认不选中或需要查看详情。
- `ConfirmationRequired`：会改变系统功能或删除不可直接恢复内容；必须单独确认。

**规则变更**：规则结果必须携带版本号；规则升级后旧计划自动失效，避免用旧扫描结果执行新逻辑。

### F06 清理预览（计划二只读版已完成；计划三执行入口已接入）

**目的**：在任何删除动作前，让用户知道“删什么、删多少、有什么后果”。

**当前页面**：按低风险、需要复核和需单独确认分组；支持逐项选择和展开证据，显示路径、规则版本、文件数、容量、恢复策略、隔离资格与权限。底部实时汇总选中容量和最高风险，所有按钮明确“生成计划/索引，不执行清理”。

**完整页面目标**：按风险分组的候选列表、路径/官方项目名称、文件数、容量、预计耗时、恢复方式、跳过原因和管理员权限提示。

**交互**：用户可按规则全选、单项取消、按容量排序、展开路径详情、查看规则说明。页面底部显示选中项目总数、总容量和最高风险等级。

**计划生成**：Rust 从完成扫描生成不可变计划，记录候选的 `metadata_digest`、观测时间和 `plan_digest`；重新校验时若扫描 ID、规则版本、允许路径、文件数量、大小或元数据摘要变化，必须回到“重新扫描”，不得进入执行层。当前计划明确标记为未授权，不执行删除。

**生命周期与审计**：计划默认仅保留 10 分钟，并绑定来源卷标识；过期或卷身份变化时必须重新扫描。扫描完成、计划生成和计划拒绝统一记录不含文件内容的本地审计事件。

**禁止行为**：不能用“全部清理”绕过高风险项目；不能在预览后静默改变目标；扫描结果过期、卷身份变化或文件已改变时必须要求重新扫描。

### F07 低风险清理（计划三受限基础版已完成）

**目的**：在可验证的范围内释放空间。

**执行顺序**：重新发现目标 → 校验卷身份和规则版本 → 校验计划摘要 → 写入开始审计 → 按项目执行 → 校验结果 → 写入结束审计。

**优先方式**：个人文件进入回收站或隔离区；系统缓存调用官方 Windows 清理接口；只有确定可再生且路径在允许根目录内的缓存才允许直接删除。

**失败处理**：单项失败记录原因并停止后续高风险项目；向用户报告实际释放容量，不能用预估容量代替结果。

**安全限制**：根目录、用户目录和系统目录不能作为递归删除目标；跳过联接点、符号链接、锁定文件和路径越界目标；确认令牌只能使用一次。

**当前开放范围**：`user-temp.v1`、`browser-cache.v1`、`thumbnail-cache.v1` 与 `build-cache.v1` 通过专用版本化允许根适配器进入应用隔离区。目录树内任一位置出现符号链接、联接点、重解析点或不可完整读取项时，整个项目跳过。回收站通过独立 Windows Shell API 执行；Windows 更新缓存没有执行能力。

**确认与重放保护**：申请确认时重新扫描，Rust 只接受计划中的候选 ID；操作系统加密随机数生成的令牌两分钟过期，并绑定执行模式。隔离确认词为“确认移入隔离区”，回收站永久清空确认词为“确认永久清空回收站”；两类候选不能混合。任意提交都会先消费令牌，执行时再次扫描并比对执行根与完整快照。

**结果模型**：每条候选返回已隔离、部分隔离或已跳过，以及真实移动容量、项目数和原因。当前不删除文件、不请求管理员权限、不调用任意命令；`execution_authorized = true` 只描述这一笔已消费确认的受限报告，不会授权原计划或其他规则。

### F08 系统维护（规划中、受限功能）

**包含项目**：休眠文件、Windows 更新下载缓存、旧更新包、系统错误报告、还原点或组件存储。

**展示要求**：每个项目必须明确说明对系统功能的影响，例如关闭休眠会影响快速启动或休眠功能。

**权限要求**：需要管理员权限时，只启动受限协议，不把管理员权限授予整个 UI 进程。

**默认策略**：高风险系统维护项目默认关闭；必须二次确认；执行前检查 BitLocker、电源、系统卷健康和待重启状态。

### F09 隔离区与恢复（计划四完成）

**目的**：为个人文件和可疑清理项提供可恢复路径。

**功能**：查看隔离项目、原始位置、移动时间、占用空间、规则来源；恢复原位置；永久删除；按保留期自动清理。

**恢复规则**：恢复前检查原路径是否存在、卷身份是否一致、权限是否足够；冲突时不覆盖，要求用户选择新位置或取消。

**隐私**：日志记录元数据，不记录文件内容；隔离区目录权限应限制为当前用户可访问。

**当前实现**：同卷使用原子重命名；跨卷使用复制、SHA-256 校验、隔离卷原子发布和源移除事务，并持久化 `Copying/CopyVerified/Restoring` 状态。启动时保守协调中断事务，不会未经确认删除源。支持 7/15/30 天保留期、1/5/10/20 GiB 容量档位、到期只标记和最多 100 项批量恢复。恢复只提交后端 `entry_id`，原位置冲突永不覆盖。

**尚未开放**：隔离区永久删除和用户自选恢复位置仍无命令或按钮；到期项目依旧可恢复。

### F10 回收站管理（计划五受限版完成）

**功能**：按卷查看回收站占用、文件数量、最早删除时间；支持恢复、清空单卷回收站或清空全部回收站。

**风险**：清空回收站属于不可逆操作，必须显示不可恢复警告和容量明细；默认不在“一键清理”中自动清空。

**当前实现**：仅系统卷候选可通过 `SHEmptyRecycleBinW` 执行，卷根由后端固定适配器解析。执行前必须生成不可变计划、完成两次新扫描并输入独立确认词“确认永久清空回收站”。结果容量明确标记为扫描估计值；该 API 边界不能接受路径，也不能扩展为任意永久删除。

### F11 磁盘健康（只读版已完成）

**目的**：避免在磁盘健康异常时执行大规模清理或分区变更。

**展示**：健康状态、设备类型、温度（若可用）、存储提供程序与自监测结论、读写错误、寿命估计、通电时间、固件、总线、介质、扇区大小、BitLocker 卷汇总和数据更新时间。

**限制**：无法读取的字段显示“不可用”，不推断为“健康”；健康告警时允许查看和备份建议，但禁用分区写操作。

**当前实现**：Windows 适配器从受信任系统路径执行编译期固定、无调用方参数的 `Get-Disk`、`Get-PhysicalDisk`、`Get-StorageReliabilityCounter`、`Get-Partition` 和 `Get-BitLockerVolume` 查询。优先用 `UniqueId` 精确关联计划六的物理磁盘身份，必要时退化为磁盘号匹配；无法确认身份时结果为未知。Rust 领域层使用保守阈值评估严重、注意、未知和良好状态，只有提供程序、自监测、身份和预期可靠性证据完整且无告警时才显示良好。

**隐私和兼容性**：完整序列号在 PowerShell 输出前截断，Rust、Tauri、Vue 和导出报告最多保留末四位。Windows Storage Reliability Counter 是当前统一来源，不保证每种设备、USB 桥接器或驱动都提供原始厂商专有 SMART 属性；缺失字段不会被补零或推断正常。该命令不接受参数，不提权，不提供修复、写盘或厂商命令入口。浏览器模式只使用 Fixture。

### F12 分区拓扑（计划六只读版已完成）

**目的**：用图形方式解释磁盘布局，减少用户误操作。

**展示**：物理磁盘、分区顺序、起始偏移、容量、文件系统、卷标、EFI/恢复/系统标识、未分配空间和 BitLocker 状态。

**交互**：点击分区查看详情；支持缩放和横向滚动；危险分区使用文字标签和图案辅助，不仅依赖颜色。

**只读原则**：初期只提供查看、刷新、导出报告，不显示执行按钮。

**当前实现**：Windows 适配器通过固定、无调用方参数的 Storage/CIM 查询读取物理磁盘和分区，Rust 根据偏移补出未分配区域，并对 EFI、Microsoft Reserved、恢复、系统、启动和未知区域分类。Apple 风格拓扑条支持横向滚动、文字/纹理保护标签、点击数据分区查看容量、文件系统、BitLocker、快照、健康、偏移和 GUID。浏览器模式只显示静态 Fixture。

**发现限制**：字段不可用时显示“未知/不可用”，同时产生发现警告；未知不会被推断为健康。卷影副本和物理介质映射无法可靠确认时采用保守阻塞。

### F13 分区合并预演（计划六只读版已完成）

**目的**：在真实写操作前判断两个相邻分区是否有合并可能，并解释阻塞原因。

**检查项**：分区相邻关系、可移动空间、文件系统支持、系统/EFI/恢复属性、BitLocker、动态磁盘、存储空间、快照、坏块、挂载状态和数据迁移需求。

**输出**：可行/不可行结论、模拟后的拓扑、需要迁移的数据、预计耗时、是否需要重启、风险等级和阻塞原因。

**重要限制**：预演通过不代表执行一定成功；执行前必须重新发现并使旧计划失效。

**当前实现**：UI 只提交后端分区 ID。Tauri 每次预演前重新发现，Rust 验证同一物理磁盘、左目标/右源相邻顺序、稳定 GUID、普通 NTFS 数据分区、基本磁盘、健康在线、非只读、BitLocker 关闭、无快照、无未纠正介质错误且迁移数据量可读。每个失败检查返回独立代码、原因和恢复建议；通过时生成移除源分区并扩展目标容量的模拟拓扑、迁移字节和保守耗时估算。

**执行边界**：风险始终标记为高，`execution_authorized = false`，无论结论如何都不生成令牌或计划写入。当前没有删除、格式化、缩放、迁移、`diskpart`、任意 shell 或重启命令。用户可导出不含文件内容的 JSON 预演报告。

### F14 分区写操作（计划七安全基础已完成，真实写入关闭）

**目的**：在经过独立安全评审后执行卷调整或合并。

**执行前置条件**：备份建议已展示；用户明确确认；计划摘要匹配；磁盘唯一标识和分区 GUID 匹配；电源稳定；BitLocker 和文件系统状态允许；恢复状态已写入。

**默认禁止**：当前系统分区、EFI 分区、恢复分区、健康异常卷、身份无法确认的卷和有未完成恢复任务的磁盘。

**恢复**：需要离线操作时写入版本化恢复状态；重启后只能继续同一计划或安全停止；任何状态不匹配都停止而不是猜测。

**计划七当前实现**：后端每次评估重新发现拓扑、运行计划六预演，并通过固定只读查询读取供电和 Windows 待重启标记。Rust 生成五分钟过期、绑定预演 ID、拓扑时间、系统证据、磁盘/分区身份、迁移容量和恢复协议版本的 SHA-256 不可变计划。普通用户勾选不能作为备份证据；在独立备份提供程序实现前，该项保持阻塞。

**恢复协议**：领域层实现 `Planned → PreflightValidated → MigrationPrepared → MutationStarted → Verifying → Completed` 状态机。写入前中断进入 `SafeStopped`，潜在元数据写入开始后的中断或验证失败进入 `ManualRecoveryRequired`。越序事件、时间回退和故障注入均有单元测试。

**命令边界**：`assess_partition_merge_safety` 只接受源/目标后端 ID，不接受路径、盘符、偏移、命令或确认短语。返回值固定 `execution_authorized = false`、`write_capability_present = false`。界面只展示计划、检查、阻塞项和恢复策略，不存在执行按钮。

### F15 历史与审计（执行审计基础已完成）

**记录内容**：扫描时间、扫描范围、规则版本、预估容量、计划摘要、实际释放容量、失败项、跳过原因、权限状态和应用版本。

**用户功能**：按时间筛选、查看详情、导出脱敏报告、恢复隔离项、查看失败原因。

**隐私要求**：不上传文件名、文件内容或完整敏感路径；本地日志支持保留期限和一键清除。

**当前实现**：记录清理扫描完成、计划生成/拒绝、隔离区索引生成、确认签发、执行开始/完成和恢复开始/结果，最多保留 200 条、最新在前。文件系统写入边界前必须先成功持久化开始事件；事件仅包含规则 ID、候选数量、容量、安全原因和关联 ID，不包含文件内容。状态采用临时文件与备份替换，损坏 JSON 会被安全忽略。筛选、导出和一键清除仍在后续规划中。

### F16 自动维护（规划中、受限功能）

**功能**：按周或按月运行只读扫描；仅在用户允许时自动执行低风险规则；高风险规则只提醒不自动执行。

**保护机制**：空闲时运行、使用电源策略、磁盘空间不足时提醒、笔记本电量低时暂停、系统更新或备份任务运行时避让。

**通知**：展示扫描完成、发现容量、跳过项目和需要用户确认的项目，不使用夸大的“系统危险”文案。

### F17 设置与隐私（规划中）

**设置项**：默认扫描范围、忽略目录、规则开关、隔离区保留期、自动维护计划、通知、日志级别、主题、语言和启动行为。

**安全限制**：忽略目录不能让特权层跳过安全校验；用户选择的扫描路径必须规范化并限制在可访问范围；设置变更写入版本化配置。

### F18 更新与发布（规划中）

**更新流程**：检查 GitHub Release 的版本元数据和 SHA-256；下载后校验签名和哈希；安装前展示版本、变更说明和权限。

**发布要求**：NSIS 安装包和 portable ZIP 只由 GitHub Windows Runner 生成；PR 和日常 push 不生成安装包；公开发布前应配置 Authenticode 签名。

**失败处理**：哈希或签名不匹配时拒绝安装；下载中断支持重试；升级失败保留上一个可启动版本。

## 5. 统一安全流程

涉及删除、系统修改或分区写入的操作必须遵循：

1. 只读发现目标。
2. 生成不可变计划。
3. 展示目标、容量、风险和影响。
4. 用户明确确认。
5. 特权层重新发现并校验身份。
6. 执行最小范围操作。
7. 校验结果并写入审计记录。

任意一步失败，操作进入停止或部分失败状态；不自动扩大范围，不重试高风险操作，不接受任意 shell 文本。

## 6. 典型用户流程

### 普通用户清理缓存

打开首页 → 开始智能扫描 → 查看浏览器缓存和临时文件 → 保留默认安全项目 → 打开清理预览 → 确认 → 查看实际释放容量和跳过项。

### 用户处理大文件

选择磁盘 → 运行空间扫描 → 按目录或文件类型排序 → 查看路径和最近访问信息 → 手动选择文件 → 移入回收站或隔离区 → 需要时恢复。

### 高级用户预演分区合并

打开分区管理 → 查看磁盘拓扑 → 选择相邻分区 → 运行可行性检查 → 阅读阻塞原因和恢复建议 → 导出预演报告。初期流程到此结束，不执行写操作。

## 7. 统一错误与状态文案

- 扫描中：`正在读取磁盘信息，不会修改文件`
- 需要确认：`此项目可能影响系统功能，请查看详情后确认`
- 权限不足：`当前权限无法读取该项目，未执行任何修改`
- 目标变化：`磁盘状态已变化，原计划已失效，请重新扫描`
- 部分失败：`部分项目未完成，已停止后续高风险操作`
- 不支持：`当前磁盘状态暂不支持此操作，未执行任何修改`

禁止使用“100% 安全”“一键解决所有问题”“发现严重风险”等无法验证或制造恐慌的表达。

## 8. 功能验收原则

每个功能上线前必须具备：领域单元测试、平台适配测试、Tauri command 契约测试、关键 UI 测试、取消/超时/权限不足/磁盘断开/路径变化测试，以及对应 Rustdoc、JSDoc 和安全文档更新。

当前仓库可核验的已完成内容是：P0 工程基础、Apple 风格首页、P1 只读卷发现、计划一空间扫描、计划二清理规则与预览、计划三受限执行、计划四/五的隔离策略、批量/跨卷恢复、四类缓存适配器和回收站官方 API、计划六的物理分区拓扑与合并可行性预演、F11 磁盘健康只读检测，以及计划七的分区不可变安全计划、系统证据和恢复状态机。Windows Update 管理员维护、隔离永久删除、厂商专有原始 SMART 属性和任何真实分区写操作仍按规划功能处理。
