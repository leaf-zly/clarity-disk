# 特权与破坏性操作安全规范

## 强制流程

任何文件删除、系统设置修改或分区写操作必须按以下顺序执行：

1. 只读发现目标。
2. 生成不可变操作计划。
3. 展示路径、容量、风险和影响。
4. 用户明确确认。
5. 特权服务重新发现并校验目标身份。
6. 执行最小范围操作。
7. 校验结果并写入审计日志。

## 文件清理

- 根目录、用户目录和系统目录不能作为递归删除目标。
- 路径必须规范化并验证仍位于允许的清理根目录下。
- 默认跳过重解析点、符号链接、联接点和锁定文件。
- 系统管理的缓存优先调用官方清理接口。
- 个人文件默认进入回收站或隔离区。

### 计划二已实现的只读保护

- Windows 更新缓存仅允许读取 `%SystemRoot%\SoftwareDistribution\Download`，默认不选中；不会停止服务、删除缓存或请求提权。
- 清理计划只接受最新预览的 `scan_id` 和候选 ID；路径、风险、规则版本和元数据摘要由 Rust 从预览复制。
- 审计最多保留 200 条安全摘要，不记录文件内容；状态文件损坏时安全忽略。

### 计划三已实现的受限写入保护

- `user-temp.v1`、`browser-cache.v1`、`thumbnail-cache.v1` 与 `build-cache.v1` 仅能通过版本化允许根适配器进入隔离区。
- `recycle-bin.v1` 只能调用 `SHEmptyRecycleBinW`，必须使用独立永久确认词，且不能与隔离候选混合。
- Windows 更新缓存继续只读，未来必须使用独立最小权限管理员服务。
- 不删除、不提权、不启动系统服务、不执行 shell；只移动 TEMP/TMP 精确允许根下的直接子项。
- UI 不提交路径。执行命令只接受后端计划 ID、候选 ID、一次性令牌和精确确认词；恢复只接受后端 `entry_id`。
- 确认令牌由操作系统加密随机数生成，两分钟过期，绑定内存中的计划与候选集合；第一次提交即消费，错误、过期或执行失败均不能重放。
- 签发令牌和执行前各重新扫描一次；规则版本、路径、容量、项目数、风险、权限、恢复策略、隔离资格或元数据摘要变化都会拒绝执行。
- 目录根、全部祖先和整棵待移动子树拒绝符号链接、联接点及重解析点；不可完整读取、锁定或并发变化项目安全跳过。
- 文件移动前先持久化 `Staging` 恢复记录和执行开始审计；应用启动时保守核对未完成记录。
- 恢复来源必须位于应用隔离根，恢复目标必须再次匹配条目所属规则的动态允许根；发现同名冲突时不覆盖。
- 跨卷传输必须复制到后端命名临时路径、校验完整性并在目标卷原子发布；启动恢复不得自动删除同时存在的源副本。
- 隔离保留期和容量只接受固定档位；到期只标记。隔离区永久删除仍没有命令面。
- `execution_authorized` 只属于单次执行报告，不会授权不可变计划、其他规则或后续请求。

## 分区操作

- 使用磁盘唯一标识、分区 GUID、起始偏移和容量共同定位目标。
- 执行前重新检查 BitLocker、文件系统、磁盘健康和供电状态。
- EFI、恢复分区和当前系统分区默认禁止删除。
- 合并分区必须先验证数据迁移结果，再删除源分区。
- 离线操作需要版本化恢复状态，能够在重启后判断继续或停止。

## 特权协议

- 使用枚举型操作，不接受任意 shell 字符串。
- 所有字段限制长度、字符集和数值范围。
- 每个确认令牌只允许执行一次，并绑定操作计划摘要。
- 审计日志不得记录用户文件内容或不必要的敏感路径。
