# 特权与破坏性操作安全规范

## 强制流程

任何文件删除、系统设置修改或分区写操作必须按以下顺序执行：

1. 只读发现目标。
2. 生成不可变操作计划。
3. 展示路径、容量、风险和影响。
4. 用户明确确认。
5. 特权服务重新发现并校验目标身份。
6. 执行最小范围操作。
7. 校验结果并写入审计日志。

## 文件清理

- 根目录、用户目录和系统目录不能作为递归删除目标。
- 路径必须规范化并验证仍位于允许的清理根目录下。
- 默认跳过重解析点、符号链接、联接点和锁定文件。
- 系统管理的缓存优先调用官方清理接口。
- 个人文件默认进入回收站或隔离区。

### 安全清理的只读保护

- Windows 更新缓存仅允许读取 `%SystemRoot%\SoftwareDistribution\Download`，默认不选中；不会停止服务、删除缓存或请求提权。
- 清理计划只接受最新预览的 `scan_id` 和候选 ID；路径、风险、规则版本和元数据摘要由 Rust 从预览复制。
- 审计最多保留 200 条安全摘要，不记录文件内容；状态文件损坏时安全忽略。

### 低风险清理的受限写入保护

- `user-temp.v1`、`browser-cache.v1`、`thumbnail-cache.v1` 与 `build-cache.v1` 仅能通过版本化允许根适配器进入隔离区。
- `recycle-bin.v1` 只能调用 `SHEmptyRecycleBinW`，必须使用独立永久确认词，且不能与隔离候选混合。
- Windows 更新缓存继续只读，未来必须使用独立最小权限管理员服务。
- 不删除、不提权、不启动系统服务、不执行 shell；只移动 TEMP/TMP 精确允许根下的直接子项。
- UI 不提交路径。执行命令只接受后端计划 ID、候选 ID、一次性令牌和精确确认词；恢复只接受后端 `entry_id`。
- 确认令牌由操作系统加密随机数生成，两分钟过期，绑定内存中的计划与候选集合；第一次提交即消费，错误、过期或执行失败均不能重放。
- 签发令牌和执行前各重新扫描一次；规则版本、路径、容量、项目数、风险、权限、恢复策略、隔离资格或元数据摘要变化都会拒绝执行。
- 目录根、全部祖先和整棵待移动子树拒绝符号链接、联接点及重解析点；不可完整读取、锁定或并发变化项目安全跳过。
- 文件移动前先持久化 `Staging` 恢复记录和执行开始审计；应用启动时保守核对未完成记录。
- 恢复来源必须位于应用隔离根，恢复目标必须再次匹配条目所属规则的动态允许根；发现同名冲突时不覆盖。
- 跨卷传输必须复制到后端命名临时路径、校验完整性并在目标卷原子发布；启动恢复不得自动删除同时存在的源副本。
- 隔离保留期和容量只接受固定档位；到期只标记。永久删除使用独立 entry-ID 摘要、两分钟令牌、精确确认词和整树重解析点校验。
- `execution_authorized` 只属于单次执行报告，不会授权不可变计划、其他规则或后续请求。

## 分区操作

- 使用磁盘唯一标识、分区 GUID、起始偏移和容量共同定位目标。
- 执行前重新检查 BitLocker、文件系统、磁盘健康和供电状态。
- EFI、恢复分区和当前系统分区默认禁止删除。
- 合并分区必须先验证数据迁移结果，再删除源分区。
- 离线操作需要版本化恢复状态，能够在重启后判断继续或停止。

### 分区发现的只读保护

- `get_partition_topology` 不接受任何调用方输入；`preview_partition_merge` 只接受后端发现的源/目标分区 ID，并在计算前重新读取拓扑。
- Windows 正常路径使用编译期固定的 Storage IOCTL、进程内 WMI/COM、Power 和 Registry API，不启动 shell；WMI 只执行固定的只读查询并补充磁盘/分区管理状态、动态磁盘、Storage Spaces 和卷影副本证据。普通权限下未覆盖的 BitLocker 与可靠性信号保持未知。仅在原生查询失败或需要 ACL/恢复证明时，才从 `SystemRoot` 下的受信任位置启动固定 PowerShell 兼容查询。调用方不能提交脚本、命令、参数、路径、盘符、GUID 或 `diskpart` 文本。
- 自动维护保护探测使用 User32 `GetLastInputInfo`、Power `GetSystemPowerStatus` 和 Toolhelp 进程快照读取空闲、电源、更新及备份状态，不启动 shell；任一原生信号读取失败都会阻止自动扫描。
- 分区身份由磁盘唯一标识、分区 GUID、起始偏移和容量共同描述；GUID 缺失、身份重复或容量越界会失败关闭。
- 只有同一物理磁盘上“左侧目标 + 紧邻右侧源”的普通 NTFS 数据分区可能通过预演。跨磁盘、反向或不相邻布局均返回可解释阻塞。
- EFI、Microsoft Reserved、恢复、当前系统、启动、未分配和未知分区默认受保护。
- BitLocker 开启/暂停/未知、动态磁盘、存储空间、布局未知、卷影副本存在/未知、磁盘或卷离线/只读/健康未知，以及介质可靠性计数存在未纠正错误或不可用时均阻塞。
- 当前卷影副本发现采用保守策略：只要发现无法安全映射的快照依赖，就不会把候选误判为可行。
- 预演只输出检查证据、迁移字节估算和模拟布局，`execution_authorized` 永远为 `false`；命令面中不存在分区删除、格式化、缩放、数据迁移、重启任务或确认令牌。
- 浏览器开发模式只使用静态 Fixture，不调用 Windows 存储提供程序，也不执行真实磁盘操作。

### 磁盘健康的只读保护

- `get_disk_health_snapshot` 不接受任何参数，只能运行编译期固定的 Windows Storage 查询；没有脚本、路径、盘符、磁盘号或厂商命令输入面。
- 健康正常路径通过 Windows Storage IOCTL 读取设备描述、容量、总线、固件、扇区和温度；兼容路径才从受信任的 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` 启动普通用户只读进程。两条路径均不申请管理员权限，不调用修复、写盘、格式化或分区命令。
- `UniqueId` 精确映射优先于 Windows 磁盘号映射；无法安全关联可靠性记录时身份和健康结论均标记未知。
- 完整设备序列号在 PowerShell JSON 输出前截断，领域模型拒绝超过四个字符的序列后缀；导出报告显式选择允许字段，避免未来平台字段意外泄露。
- 离线、提供程序异常、自监测失败、未纠正错误、高温和高磨损会生成严重信号；证据缺失生成未知信号。只有完整正向证据且不存在告警时才显示良好。
- Windows Storage Reliability Counter 并非所有设备和驱动都支持，厂商专有原始 SMART 属性缺失时保持“不可用”，禁止补零、猜测或显示为通过。
- 所有健康结果固定 `partition_writes_blocked = true`；健康页面只有刷新和脱敏导出，不存在修复、管理员操作或分区执行按钮。

### 分区安全评估基础

- 完整威胁与信任边界见 [分区写操作威胁模型](partition-write-threat-model.md)。安全基础完成不等于真实写入获得授权。
- `assess_partition_merge_safety` 只接受源/目标后端 ID，并在同一请求中重新发现拓扑、重新运行预演和读取系统证据；不接受路径、盘符、GUID、偏移、命令或确认文本。
- 不可变计划使用 SHA-256 绑定预演 ID、拓扑和证据时间、磁盘/分区身份、迁移容量、有效期与恢复协议版本；证据窗口为 60 秒，计划五分钟过期。
- 固定只读 Windows 原生查询检查系统电池供电以及 CBS、Windows Update 和待文件重命名标记；检测到备份凭据时再使用兼容查询验证 ACL 和恢复证明。电池放电、待重启、查询失败或未知状态均阻塞。
- 普通用户勾选、文本确认或本机卷影副本都不能证明备份可恢复。独立提供程序要求管理员保护凭据、另一物理磁盘和实际恢复摘要；凭据缺失或失效时保持阻塞。
- 恢复状态机只接受规定顺序。元数据写入前中断进入安全停止；潜在写入开始后的中断和验证失败进入人工恢复，不能自动猜测继续。
- `execution_authorized = false`、`write_capability_present = false` 仍是只读评估契约；独立执行准备只有在全部证据和双重门禁通过时才签发另一个一次性挑战，不能复用评估结果授权。

## 特权协议

### 受控执行的管理员边界

- 高权限能力位于独立一次性代理，Vue 和 Tauri 主进程不整体提权。
- 协议 v1 只有固定枚举，拒绝任意 shell、可执行文件、注册表路径、盘符或文件路径。
- 管理员维护请求两分钟过期，绑定随机一次性令牌、精确确认词、请求 ID 和请求 SHA-256；首次提交即消费。
- 管理员代理重新发现系统目标；Windows Update 缓存只允许固定系统目录且整树拒绝重解析点。
- 分区计划 v2 绑定磁盘 ID/号、两个 GUID/分区号/偏移/容量/剩余空间以及供电、待重启和独立备份结论。
- 分区写入同时要求编译功能和管理员所有的 ProgramData 运行时标志；未知状态一律失败关闭。
- 数据迁移使用后端重新发现的卷根、固定目标目录和 `robocopy /COPYALL`，随后独立读取并计算 SHA-256 树摘要。
- `MutationStarted` 恢复日志刷新成功前不得删除源分区；此后失败只能进入人工恢复。

完整协议、状态与发布方式见 `docs/architecture/privileged-broker-and-partition-executor.md`。

- 使用枚举型操作，不接受任意 shell 字符串。
- 所有字段限制长度、字符集和数值范围。
- 每个确认令牌只允许执行一次，并绑定操作计划摘要。
- 审计日志不得记录用户文件内容或不必要的敏感路径。
