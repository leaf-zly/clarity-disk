# 在线更新运维说明

## 用户流程

在“设置 → 在线更新”手动检查、查看更新说明、下载，再勾选关闭应用的确认并点击“安装并重启”。没有自动下载、静默安装或后台升级。关闭更新检查设置后不再允许新的检查和下载；已经验签的安装包仍可由用户确认安装。

0.1.1 是首个具备在线安装能力的版本，0.1.0 用户必须手动安装一次。只有更高版本会触发更新，不支持降级。浏览器预览不调用原生更新器，不模拟下载成功。

## 信任边界

- 采用 Tauri 官方 updater 2.10.1；独立更新公钥固定在应用配置中，私钥仅用于 GitHub Actions 签名。
- 下载使用 HTTPS，验证 TLS，不允许自定义下载地址、关闭证书检查或覆盖公钥。
- 下载结束事件不等于校验成功。必须等待 updater 的签名校验返回成功才能出现安装入口；失败时丢弃资源。
- 清理、恢复、永久删除、策略/设置写入及管理员工作由进程内互斥门禁保护；正在执行时拒绝更新安装。用户还需先停止独立只读扫描，避免进程退出丢失未完成扫描。
- 测试版只有专用更新签名，没有 Windows Authenticode 发布者签名，界面明确告知可能出现安全提示。正式发布的证书、SHA-256、来源证明和安装验收门禁不变。
- 更新私钥不得提交仓库、输出日志或随安装包分发；本机恢复副本位于当前用户 LocalAppData 下 `ClarityDiskBuildKeys`，目录 ACL 仅允许当前用户和 SYSTEM。应另行备份至受控密钥保管位置。

## 两条通道

| 构建           | 更新清单                                             | 版本安装包                          |
| -------------- | ---------------------------------------------------- | ----------------------------------- |
| 测试版（默认） | 官方仓库 `update-preview` Release 中的 `latest.json` | 不可覆盖的 `preview-vX.Y.Z` Release |
| 正式版         | 官方仓库最新正式 Release 中的 `latest.json`          | 经证书门禁验证的 `vX.Y.Z` Release   |

正式构建必须同时使用 `VITE_UPDATE_CHANNEL=stable` 和 `tauri.updater-stable.conf.json`。测试版不会因出现正式版而自行切换信任通道；初次切换需安装正式发行版。

## 发布步骤

1. 同步提升根 package.json、桌面 package.json、Cargo.toml 工作区版本与 tauri.conf.json，更新 Cargo.lock。
2. 新建 `docs/release/X.Y.Z-preview.md` 更新说明。不得复用已经发布的版本号。
3. 提交并推送；运行 `preview-package.yml`，需要上线更新时设置 `publish_update=true`。
4. 工作流生成 `.exe`、`.exe.sig`、SHA256SUMS.txt 与 latest.json；同提交 CI 成功后才会发布。
5. 先公开不可变的版本安装包，最后上传测试版通道清单，防止客户端看到缺失安装包的更新。
6. 检查清单版本、下载 URL、签名，以及下载后的 SHA-256。不要在开发机器打包或执行静默安装测试。

所需 GitHub Secret：`TAURI_SIGNING_PRIVATE_KEY`；若私钥有密码，再设置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。没有密钥时应构建失败，不能发布无签名更新。更换密钥会影响所有已安装版本，必须设计轮换/手动升级方案，不能直接覆盖现有密钥。

正式工作流额外要求现有 WINDOWS_CERTIFICATE_* Secrets。正式清单挂在经过校验的草稿 Release，人工发布并设为最新版本后才对正式客户端可见。

## 测试范围

- 前端：禁用更新、检查超时、签名失败、下载与验签状态分离、确认安装、禁止重复点击、离开后的资源释放、安装门禁拒绝和失败恢复。
- Rust：活动任务阻止退出预留、预留期间拒绝新操作、失败后的门禁恢复。
- 发布脚本：版本与文件名检查、通道隔离、签名编码检查、固定官方不可变安装地址。
- 真机跨版本更新涉及应用退出和安装，必须在专用测试环境验收，不在用户正在工作的设备上自动执行。
