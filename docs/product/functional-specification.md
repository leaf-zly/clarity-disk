# 澄盘功能说明书

> 版本：0.1 · 日期：2026-08-13 · 文档状态：产品评审稿

## 1. 文档说明

这是一份面向产品、设计、开发、测试和发布团队的功能说明书。它描述“澄盘”要解决的问题、每一个功能的使用方式、展示信息、权限边界、失败处理和验收条件。

状态标记：

- **已完成**：仓库中已有可运行实现，并通过对应质量检查。
- **开发中**：技术路线已确定，正在拆分为代码任务。
- **规划中**：已列入产品范围，但必须完成前置安全评审后才能实现。
- **受限功能**：涉及删除、管理员权限、重启或分区写入，默认不可直接执行。

## 2. 产品定位

澄盘是一款 Windows 本地磁盘管理工具，核心价值是“看得清、删得稳、改得明白”。它先通过只读扫描建立可信信息，再让用户查看影响、确认操作，最后由受控执行层完成低风险维护。产品不以“一键清理所有文件”为目标，不隐藏风险，也不把未知文件误判为垃圾。

## 4. 详细功能描述

### F01 首页仪表盘（已完成）

**目的**：让用户打开应用后，在一个页面内理解当前磁盘状态。

**页面内容**：

- 顶部问候语、当前状态摘要和“开始智能扫描”按钮；
- 系统盘总容量、已使用容量、可用容量和使用百分比；
- 应用、系统、文件、开发缓存等空间分类；
- 智能清理建议卡片，显示预计可释放空间和风险等级；
- 磁盘健康、上次清理、自动维护等状态卡片；
- 本月累计释放空间和最近维护活动。

**交互规则**：

1. 页面加载时显示骨架或加载状态。
2. 数据读取失败时显示可理解的错误和重试按钮。
3. “开始智能扫描”只启动扫描，不直接删除文件。
4. 浏览器模式使用 fixture，桌面模式通过 Tauri command 获取数据。

**安全边界**：首页不接受路径、不执行 shell、不直接访问文件系统。当前清理建议和健康信息中仍有演示数据，界面必须保持“预览”语义。

**验收**：桌面布局、响应式布局、键盘操作、错误状态和 4 个现有前端测试均通过。

### F02 磁盘与卷发现（已完成只读基础版）

**目的**：发现 Windows 中的物理磁盘、逻辑卷和挂载点，建立后续扫描和分区操作的稳定身份。

**当前已读取**：盘符/挂载点、卷标、文件系统、总容量、可用容量、设备类型、是否系统卷、是否可移动、是否只读和基础健康状态。磁盘唯一标识、分区 GUID、BitLocker 状态和 SMART 信息将在后续平台适配中补齐。

**用户看到的内容**：

- 磁盘列表和卷列表；
- 盘符不是唯一身份的提示；
- 系统卷、数据卷、可移动设备的标签；
- 不可访问、离线、加密或健康异常的原因。

**失败处理**：设备断开、权限不足、查询超时或字段不完整时，保留已获取的只读结果，并标记“数据不完整”，不生成任何写操作计划。

**安全边界**：只读 API；不格式化、不挂载、不修改卷标、不改变分区。

### F03 空间扫描（规划中）

**目的**：定位空间主要消耗者，为清理建议和容量分析提供证据。

**扫描范围**：用户选择的卷、目录或预设范围。预设范围包含系统临时目录、用户缓存目录、应用数据目录和开发工具缓存目录。

**扫描结果**：目录树、文件类型统计、最大文件列表、最近访问时间（若系统允许）、可跳过原因和扫描不完整标记。

**默认排除**：用户文档、桌面、下载目录、项目源码、符号链接、联接点、重解析点、虚拟文件、系统关键目录和锁定文件。

**性能要求**：低优先级运行，支持取消；不一次性把全部文件名载入内存；扫描结果可增量显示；单个异常文件不能中断整个任务。

### F04 扫描任务控制（规划中）

**目的**：让用户可以控制长时间扫描，不被不可预测的进度卡住。

**功能项**：开始、暂停、继续、取消、后台运行、限制扫描深度、限制 CPU/磁盘优先级、显示当前目录和预计剩余时间。

**状态机**：`待开始 → 扫描中 → 暂停 → 扫描中 → 已完成/已取消/失败`。终态不可重新变更；重新扫描必须生成新的 `scan_id`。

**异常**：取消后在安全边界停止，不强制终止系统线程；应用关闭时保存“未完成”状态，不把不完整结果标为完整。

### F05 清理规则中心（已完成浏览器缓存只读基础版；其余规则规划中）

**目的**：把“什么可以清理”从 UI 中抽离为可测试、可版本化的 Rust 规则。

**当前规则**：Chrome、Edge 和 Brave 默认用户配置的浏览器缓存目录。扫描器使用版本化规则 `browser-cache.v1`，仅读取目录元数据和文件大小，跳过符号链接、不可访问项和并发消失项。

**后续规则**：缩略图缓存、临时文件、回收站、应用构建缓存、Windows 更新缓存、休眠文件。

**每条规则必须说明**：规则 ID、版本、扫描范围、发现证据、文件数量、预计释放容量、风险等级、是否可恢复、是否需要管理员权限、默认是否选中。

**风险分级**：

- `Safe`：可再生缓存，删除后应用会重新生成；默认可选中。
- `Review`：可能影响历史记录、登录状态或应用体验；默认不选中或需要查看详情。
- `ConfirmationRequired`：会改变系统功能或删除不可直接恢复内容；必须单独确认。

**规则变更**：规则结果必须携带版本号；规则升级后旧计划自动失效，避免用旧扫描结果执行新逻辑。

### F06 清理预览（已完成只读基础版；执行闭环规划中）

**目的**：在任何删除动作前，让用户知道“删什么、删多少、有什么后果”。

**当前页面**：显示浏览器缓存候选路径、文件数、预计容量、风险等级、可恢复性、扫描跳过数量和“只读扫描，不会删除文件”提示；支持重新扫描。

**完整页面目标**：按风险分组的候选列表、路径/官方项目名称、文件数、容量、预计耗时、恢复方式、跳过原因和管理员权限提示。

**交互**：用户可按规则全选、单项取消、按容量排序、展开路径详情、查看规则说明。页面底部显示选中项目总数、总容量和最高风险等级。

**计划生成**：确认后 Rust 生成不可变计划，计算 `plan_digest`；前端只提交计划摘要和确认令牌，不提交任意路径列表到特权层。

**禁止行为**：不能用“全部清理”绕过高风险项目；不能在预览后静默改变目标；扫描结果过期、卷身份变化或文件已改变时必须要求重新扫描。

### F07 低风险清理（规划中、受限功能）

**目的**：在可验证的范围内释放空间。

**执行顺序**：重新发现目标 → 校验卷身份和规则版本 → 校验计划摘要 → 写入开始审计 → 按项目执行 → 校验结果 → 写入结束审计。

**优先方式**：个人文件进入回收站或隔离区；系统缓存调用官方 Windows 清理接口；只有确定可再生且路径在允许根目录内的缓存才允许直接删除。

**失败处理**：单项失败记录原因并停止后续高风险项目；向用户报告实际释放容量，不能用预估容量代替结果。

**安全限制**：根目录、用户目录和系统目录不能作为递归删除目标；跳过联接点、符号链接、锁定文件和路径越界目标；确认令牌只能使用一次。

### F08 系统维护（规划中、受限功能）

**包含项目**：休眠文件、Windows 更新下载缓存、旧更新包、系统错误报告、还原点或组件存储。

**展示要求**：每个项目必须明确说明对系统功能的影响，例如关闭休眠会影响快速启动或休眠功能。

**权限要求**：需要管理员权限时，只启动受限协议，不把管理员权限授予整个 UI 进程。

**默认策略**：高风险系统维护项目默认关闭；必须二次确认；执行前检查 BitLocker、电源、系统卷健康和待重启状态。

### F09 隔离区与恢复（规划中）

**目的**：为个人文件和可疑清理项提供可恢复路径。

**功能**：查看隔离项目、原始位置、移动时间、占用空间、规则来源；恢复原位置；永久删除；按保留期自动清理。

**恢复规则**：恢复前检查原路径是否存在、卷身份是否一致、权限是否足够；冲突时不覆盖，要求用户选择新位置或取消。

**隐私**：日志记录元数据，不记录文件内容；隔离区目录权限应限制为当前用户可访问。

### F10 回收站管理（规划中）

**功能**：按卷查看回收站占用、文件数量、最早删除时间；支持恢复、清空单卷回收站或清空全部回收站。

**风险**：清空回收站属于不可逆操作，必须显示不可恢复警告和容量明细；默认不在“一键清理”中自动清空。

### F11 磁盘健康（规划中）

**目的**：避免在磁盘健康异常时执行大规模清理或分区变更。

**展示**：健康状态、设备类型、温度（若可用）、SMART/厂商状态、读写错误、寿命估计、BitLocker 状态和数据更新时间。

**限制**：无法读取的字段显示“不可用”，不推断为“健康”；健康告警时允许查看和备份建议，但禁用分区写操作。

### F12 分区拓扑（规划中）

**目的**：用图形方式解释磁盘布局，减少用户误操作。

**展示**：物理磁盘、分区顺序、起始偏移、容量、文件系统、卷标、EFI/恢复/系统标识、未分配空间和 BitLocker 状态。

**交互**：点击分区查看详情；支持缩放和横向滚动；危险分区使用文字标签和图案辅助，不仅依赖颜色。

**只读原则**：初期只提供查看、刷新、导出报告，不显示执行按钮。

### F13 分区合并预演（规划中）

**目的**：在真实写操作前判断两个相邻分区是否有合并可能，并解释阻塞原因。

**检查项**：分区相邻关系、可移动空间、文件系统支持、系统/EFI/恢复属性、BitLocker、动态磁盘、存储空间、快照、坏块、挂载状态和数据迁移需求。

**输出**：可行/不可行结论、模拟后的拓扑、需要迁移的数据、预计耗时、是否需要重启、风险等级和阻塞原因。

**重要限制**：预演通过不代表执行一定成功；执行前必须重新发现并使旧计划失效。

### F14 分区写操作（规划中、高风险功能）

**目的**：在经过独立安全评审后执行卷调整或合并。

**执行前置条件**：备份建议已展示；用户明确确认；计划摘要匹配；磁盘唯一标识和分区 GUID 匹配；电源稳定；BitLocker 和文件系统状态允许；恢复状态已写入。

**默认禁止**：当前系统分区、EFI 分区、恢复分区、健康异常卷、身份无法确认的卷和有未完成恢复任务的磁盘。

**恢复**：需要离线操作时写入版本化恢复状态；重启后只能继续同一计划或安全停止；任何状态不匹配都停止而不是猜测。

### F15 历史与审计（规划中）

**记录内容**：扫描时间、扫描范围、规则版本、预估容量、计划摘要、实际释放容量、失败项、跳过原因、权限状态和应用版本。

**用户功能**：按时间筛选、查看详情、导出脱敏报告、恢复隔离项、查看失败原因。

**隐私要求**：不上传文件名、文件内容或完整敏感路径；本地日志支持保留期限和一键清除。

### F16 自动维护（规划中、受限功能）

**功能**：按周或按月运行只读扫描；仅在用户允许时自动执行低风险规则；高风险规则只提醒不自动执行。

**保护机制**：空闲时运行、使用电源策略、磁盘空间不足时提醒、笔记本电量低时暂停、系统更新或备份任务运行时避让。

**通知**：展示扫描完成、发现容量、跳过项目和需要用户确认的项目，不使用夸大的“系统危险”文案。

### F17 设置与隐私（规划中）

**设置项**：默认扫描范围、忽略目录、规则开关、隔离区保留期、自动维护计划、通知、日志级别、主题、语言和启动行为。

**安全限制**：忽略目录不能让特权层跳过安全校验；用户选择的扫描路径必须规范化并限制在可访问范围；设置变更写入版本化配置。

### F18 更新与发布（规划中）

**更新流程**：检查 GitHub Release 的版本元数据和 SHA-256；下载后校验签名和哈希；安装前展示版本、变更说明和权限。

**发布要求**：NSIS 安装包和 portable ZIP 只由 GitHub Windows Runner 生成；PR 和日常 push 不生成安装包；公开发布前应配置 Authenticode 签名。

**失败处理**：哈希或签名不匹配时拒绝安装；下载中断支持重试；升级失败保留上一个可启动版本。

## 5. 统一安全流程

涉及删除、系统修改或分区写入的操作必须遵循：

1. 只读发现目标。
2. 生成不可变计划。
3. 展示目标、容量、风险和影响。
4. 用户明确确认。
5. 特权层重新发现并校验身份。
6. 执行最小范围操作。
7. 校验结果并写入审计记录。

任意一步失败，操作进入停止或部分失败状态；不自动扩大范围，不重试高风险操作，不接受任意 shell 文本。

## 6. 典型用户流程

### 普通用户清理缓存

打开首页 → 开始智能扫描 → 查看浏览器缓存和临时文件 → 保留默认安全项目 → 打开清理预览 → 确认 → 查看实际释放容量和跳过项。

### 用户处理大文件

选择磁盘 → 运行空间扫描 → 按目录或文件类型排序 → 查看路径和最近访问信息 → 手动选择文件 → 移入回收站或隔离区 → 需要时恢复。

### 高级用户预演分区合并

打开分区管理 → 查看磁盘拓扑 → 选择相邻分区 → 运行可行性检查 → 阅读阻塞原因和恢复建议 → 导出预演报告。初期流程到此结束，不执行写操作。

## 7. 统一错误与状态文案

- 扫描中：`正在读取磁盘信息，不会修改文件`
- 需要确认：`此项目可能影响系统功能，请查看详情后确认`
- 权限不足：`当前权限无法读取该项目，未执行任何修改`
- 目标变化：`磁盘状态已变化，原计划已失效，请重新扫描`
- 部分失败：`部分项目未完成，已停止后续高风险操作`
- 不支持：`当前磁盘状态暂不支持此操作，未执行任何修改`

禁止使用“100% 安全”“一键解决所有问题”“发现严重风险”等无法验证或制造恐慌的表达。

## 8. 功能验收原则

每个功能上线前必须具备：领域单元测试、平台适配测试、Tauri command 契约测试、关键 UI 测试、取消/超时/权限不足/磁盘断开/路径变化测试，以及对应 Rustdoc、JSDoc 和安全文档更新。

当前仓库可核验的已完成内容是：P0 工程基础、Apple 风格首页、浏览器 fixture、Rust 领域容量校验、Windows 系统盘只读容量发现、GitHub CI 与 GitHub Release 工作流。其余功能在完成实现和 CI 验证前，均以规划功能处理。
